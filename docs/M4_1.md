# M4.1 — spotting logbook CRUD and filtering

Status: implemented.

M4.1 extends the local spotting logbook with update/delete operations and server-side filtering while keeping all data local under `/data`.

## API

List or filter observations:

```text
GET /api/v1/spotting-log
```

Supported optional query parameters:

- `icao24`
- `registration`
- `airport_ident`
- `spotting_location_id`
- `from`
- `to`
- `limit` (default 100, maximum 1000)

`from` and `to` accept either RFC3339 timestamps or `YYYY-MM-DD`. A date-only `to` value includes that entire UTC day.

Examples:

```text
GET /api/v1/spotting-log?registration=LN-NGM
GET /api/v1/spotting-log?airport_ident=ENCN&from=2026-09-01&to=2026-09-07
GET /api/v1/spotting-log?spotting_location_id=kjevik-west&limit=50
```

Update an observation:

```text
PUT /api/v1/spotting-log/{id}
```

The complete replacement entry is validated using the same rules as creation. The URL ID remains stable even if `observed_at` changes.

Delete an observation:

```text
DELETE /api/v1/spotting-log/{id}
```

Successful deletion returns HTTP 204. Unknown IDs return HTTP 404.

## Persistence

Updates and deletes retain the existing atomic-write behaviour for `/data/spotting-log.json` (or `PLANE_TOOLS_SPOTTING_LOG`). A failed replacement does not partially rewrite the active logbook.
