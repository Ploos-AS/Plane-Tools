# M5.25 — ADS-B live refresh concurrency hardening

M5.25 prevents stale live ADS-B responses from overwriting newer UI state when filter changes, manual refreshes, and the auto-refresh timer overlap.

## Behaviour

- Each live refresh receives a monotonically increasing sequence number.
- Starting a new refresh aborts the previous in-flight snapshot request with `AbortController`.
- A response is applied only if its sequence is still current.
- `AbortError` from a superseded request is ignored and is not shown as a receiver failure.
- The active controller is cleared only by the current request.

This provides both cancellation and a latest-request-wins guard. The sequence check remains important even when aborting because an older request may already have completed or reached application code before cancellation takes effect.

## Scope

The change is frontend-only. It does not add receiver polling, backend state, persistence, or new public API fields. Snapshot semantics and the five-second auto-refresh cadence are unchanged.
