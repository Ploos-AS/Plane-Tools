# M5 — ADS-B receiver integration foundation

M5 adds an optional, read-only integration with a local readsb or dump1090 receiver.

Plane Tools does not send receiver data to an external tracking provider. The integration reads the receiver's local `data/aircraft.json` endpoint over HTTP(S).

## Configuration

Set:

```text
PLANE_TOOLS_ADSB_URL=http://readsb:8080
```

The URL is optional. If it is omitted, ADS-B integration is disabled while the rest of Plane Tools remains fully usable.

Optional timeout:

```text
PLANE_TOOLS_ADSB_TIMEOUT=3s
```

The timeout uses Go duration syntax such as `500ms`, `2s`, or `5s`.

## API

### Receiver status

```text
GET /api/v1/adsb/status
```

The response reports whether a receiver is configured, whether it is reachable, the normalized base URL, current aircraft count, receiver message count when available, and the generation timestamp from `aircraft.json`.

A configured but unreachable receiver is reported in the status body without making the Plane Tools process unhealthy.

### Live aircraft

```text
GET /api/v1/adsb/aircraft
```

The endpoint returns a normalized local view of currently observed aircraft. Fields can include:

- ICAO24 hex address
- flight/callsign
- registration and type code when readsb provides them
- latitude / longitude
- barometric altitude in feet
- ground speed in knots
- track
- seconds since last observation
- message count

Plane Tools understands readsb-style `alt_baro` / `gs` fields and classic dump1090-style `altitude` / `speed` fields.

## Failure behavior

- disabled integration: status remains available and reports `configured: false`
- unreachable receiver: status reports `reachable: false`; aircraft endpoint returns HTTP 502
- non-200 receiver response: treated as receiver failure
- malformed JSON: treated as receiver failure
- receiver access is bounded by the configured timeout

## M5 scope

M5 is deliberately read-only. It establishes a small local receiver boundary without polling in the background, persistence, maps, external APIs, or automatic logbook writes.

The natural follow-up is M5.1: live-aircraft web UI and a one-click path from a locally observed aircraft to a spotting-log entry.
