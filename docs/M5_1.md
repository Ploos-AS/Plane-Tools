# M5.1 — Live ADS-B web UI

M5.1 exposes the M5 local readsb/dump1090 integration in the embedded Plane Tools web UI.

## Receiver status

The UI calls `GET /api/v1/adsb/status` and shows whether the receiver is configured and reachable. Receiver problems remain isolated from the rest of Plane Tools.

## Live aircraft

The live aircraft panel calls `GET /api/v1/adsb/aircraft` and displays normalized local receiver data including aircraft identity, callsign, altitude, ground speed, track and receiver age when present.

Aircraft are shown in a stable identity-oriented order. No third-party tracking provider is contacted.

## Refresh behavior

- Manual refresh is always available.
- Auto-refresh is enabled by default at a five-second interval.
- Auto-refresh can be disabled in the UI.

This is deliberately polling-based for the first live UI milestone. It avoids adding WebSocket/SSE complexity before the receiver adapter and UI behavior are proven.

## Add sighting from live aircraft

Each live aircraft row has an **Add sighting** action. It pre-fills the existing local logbook form with:

- ICAO24
- registration when available
- ADS-B callsign as a note when available

The user can then choose the saved spotting location / airport context and submit through the existing `POST /api/v1/spotting-log` workflow.

M5.1 does not auto-log aircraft. A spotting observation is only persisted after the user submits the logbook form.

## Privacy and scope

All live data comes from the configured local `PLANE_TOOLS_ADSB_URL`. The UI adds no cloud dependency, analytics service or external JavaScript dependency.
