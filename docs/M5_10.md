# M5.10 — ADS-B observability

M5.10 adds lightweight, local diagnostics for the ADS-B ingestion path without adding Prometheus or any external telemetry dependency.

## Endpoint

`GET /api/v1/adsb/diagnostics`

The response contains only local counters and timing data:

- `cache_ttl_ms`
- `cache_hits`
- `cache_misses`
- `cache_coalesced`
- `upstream_fetches`
- `upstream_errors`
- `last_fetch_latency_ms`
- `last_success_at` when at least one successful upstream fetch has completed

## Privacy and security

The diagnostics response does not expose:

- receiver URL
- receiver hostname
- URL userinfo / credentials
- receiver coordinates
- aircraft data

The endpoint is intended for local troubleshooting and health inspection.

## Semantics

A cache hit means a caller reused a successful snapshot younger than the one-second cache TTL.

A cache miss means Plane Tools became the caller responsible for an upstream `aircraft.json` fetch.

A coalesced request means a caller arrived while another upstream fetch was already in progress and waited for that fetch instead of starting another.

Upstream errors count failed receiver fetch attempts. Failed responses are not cached.

`last_fetch_latency_ms` records the duration of the most recent upstream attempt, successful or failed. `last_success_at` records only successful upstream ingestion.

## Acceptance

- [x] Local diagnostics endpoint exists.
- [x] Cache hit/miss/coalesced counters are available.
- [x] Upstream fetch/error counters are available.
- [x] Last upstream latency is available.
- [x] Last successful fetch timestamp is available.
- [x] Receiver URL and credentials are not exposed.
- [x] No Prometheus or external telemetry dependency is introduced.
