# M5.7 — ADS-B receiver hardening

M5.7 hardens the local readsb/dump1090 integration without changing the local-first architecture.

## Security and privacy

- `/api/v1/adsb/status` no longer exposes the configured receiver base URL.
- Receiver URLs that contain HTTP basic-auth credentials therefore do not leak through the public status API or web UI.
- The web UI no longer references `status.base_url`.

## Fetch hardening

- `aircraft.json` responses are limited to 8 MiB.
- Oversized responses fail with `error_code: response_too_large`.
- ADS-B requests use a dedicated `http.Client` with the configured receiver timeout.
- The request context is also bounded by the same timeout.

## Error classification

Receiver failures are classified with stable `error_code` values:

- `not_configured`
- `request_error`
- `timeout`
- `unreachable`
- `upstream_status`
- `read_error`
- `response_too_large`
- `invalid_json`
- `receiver_error` as a fallback

The human-readable `error` field is retained for diagnostics, while clients can use `error_code` for stable handling.

## Compatibility

The normalized aircraft payload and receiver-position distance/bearing fields remain unchanged. Existing readsb and dump1090 `aircraft.json` feeds continue to use the same endpoint and configuration variables.
