# M5.22 — ADS-B frontend consolidation

M5.22 removes the radar-side wrapper chain around the live ADS-B refresh and render functions.

## Previous layering

The browser loaded ADS-B behavior in layers:

1. `app.js` defined the original `refreshADSB` and `renderADSBAircraft` functions.
2. `adsb-m52.js` replaced both functions with the filtered snapshot implementation.
3. `adsb-radar.js` captured and wrapped those replacements again to add freeze, trails, selection, follow and radar rendering.

That made callback identity and initialization order difficult to reason about. Timers and event listeners could retain references from an earlier layer while later scripts replaced the globals.

## M5.22 design

`adsb-m52.js` now exposes an explicit hook registration function:

- `beforeRefresh`
- `afterRender`

The canonical filtered snapshot refresh remains in `adsb-m52.js`.

`adsb-radar.js` registers radar behavior through those hooks instead of assigning new implementations to `refreshADSB` or `renderADSBAircraft`.

### Freeze behavior

The radar `beforeRefresh` hook returns `false` while the live view is frozen. The canonical refresh function therefore skips the snapshot request while still redrawing the currently cached radar state.

When freeze is cleared, the existing canonical `refreshADSB` function is invoked normally.

### Render behavior

The radar `afterRender` hook runs after the live list has been rendered. It preserves the existing behavior for:

- trail collection and expiry
- selected-aircraft state
- selected-aircraft grace period
- follow-selected range expansion
- radar detail rendering
- live-row selection binding
- radar drawing

## Scope

M5.22 intentionally removes the highest-risk wrapper layer first. `app.js` still contains the older pre-M5.2 ADS-B definitions because it also owns the rest of the monolithic page behavior. Removing those duplicate base definitions safely is a separate follow-up refactor.

No API, persistence, receiver polling cadence, filter semantics, trail limits or selection semantics are changed by this milestone.

## Qualification

M5.22 is qualified by tests that verify:

- the explicit hook API exists in `adsb-m52.js`
- radar registers both hooks
- radar freeze can veto a refresh
- `adsb-radar.js` no longer contains the previous refresh/render wrapper variables
- `adsb-radar.js` no longer reassigns `refreshADSB` or `renderADSBAircraft`
