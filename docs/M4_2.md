# M4.2 — Logbook statistics and lifelist

M4.2 adds local statistics derived directly from the spotting log. No external service is contacted.

## API

```text
GET /api/v1/spotting-log/summary
```

The endpoint supports the same identity/date filters as logbook listing:

- `icao24`
- `registration`
- `airport_ident`
- `spotting_location_id`
- `from`
- `to`

Unlike `GET /api/v1/spotting-log`, summary calculations are not truncated by the listing `limit`; statistics cover the complete filtered dataset.

## Response

The response includes:

- `total_sightings`
- `unique_aircraft`
- `unique_icao24`
- `unique_registrations`
- `first_observation`
- `last_observation`
- counts grouped by airport
- counts grouped by spotting location
- a lifelist with first seen, last seen and sighting count per aircraft

Aircraft identity prefers ICAO24. Registration-only entries are joined to an ICAO24 identity when another observation in the selected dataset contains the same registration together with an ICAO24 value.

## Example

```sh
curl 'http://localhost:8080/api/v1/spotting-log/summary?airport_ident=ENCN&from=2026-01-01'
```

Example shape:

```json
{
  "total_sightings": 12,
  "unique_aircraft": 9,
  "unique_icao24": 8,
  "unique_registrations": 9,
  "first_observation": "2026-01-02T10:15:00Z",
  "last_observation": "2026-09-07T08:30:00Z",
  "by_airport": [{"key":"ENCN","count":12}],
  "by_spotting_location": [{"key":"kjevik-west","count":8}],
  "lifelist": []
}
```

## Acceptance

- [x] Summary is computed locally from `/data/spotting-log.json`.
- [x] Date and identity filters are supported.
- [x] Statistics are not silently capped by the listing limit.
- [x] Airport and spotting-location counts are deterministic.
- [x] Lifelist tracks first seen, last seen and sightings.
- [x] Registration-only observations can join a known ICAO24 identity.
- [x] Empty logs return zero totals and empty arrays.
