# M4 — Local spotting logbook foundation

Status: implemented

Plane Tools now includes a local-first spotting observation log stored under `/data`.

## Storage

Default path:

```text
/data/spotting-log.json
```

Override with:

```text
PLANE_TOOLS_SPOTTING_LOG
```

Writes use a temporary file plus atomic rename so a failed write does not partially replace the active log.

## API

List observations:

```text
GET /api/v1/spotting-log
```

Create an observation:

```text
POST /api/v1/spotting-log
```

Example body:

```json
{
  "observed_at": "2026-09-07T08:00:00Z",
  "icao24": "4787A2",
  "registration": "LN-NGM",
  "spotting_location_id": "kjevik-west",
  "airport_ident": "ENCN",
  "notes": "west apron"
}
```

`observed_at` must be RFC3339. If omitted on POST, Plane Tools records the current UTC time.

At least one of `icao24` or `registration` is required. ICAO24 is normalized to uppercase and must contain exactly six hexadecimal characters. Registration is normalized to uppercase.

If `spotting_location_id` is supplied it must reference a saved local spotting location. When that location has an `airport_ident` binding and the observation does not explicitly supply one, the airport binding is inherited automatically.

If `airport_ident` is supplied it must exist in the loaded local airport database.

## Ordering and IDs

GET responses are sorted newest observation first. Each observation receives a deterministic timestamp-derived ID, with numeric suffixes added when multiple observations share the same timestamp.
