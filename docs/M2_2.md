# M2.2 — Aircraft dataset ingestion/update tooling

Status: implemented

## Goal

Provide a controlled, local way to turn larger CSV aircraft sources into the
canonical Plane Tools dataset consumed from `/data/aircraft.csv`.

## Command

```sh
plane-tools import-aircraft --input source.csv --output /data/aircraft.csv
```

When `--output` is omitted, Plane Tools uses `PLANE_TOOLS_AIRCRAFT_CSV` and then
falls back to `/data/aircraft.csv`.

## Accepted source columns

The importer maps common aliases to the canonical fields:

- ICAO24: `icao24`, `hex`, `icao`, `modes`, `modeshex`
- registration: `registration`, `reg`, `tail`, `tailnumber`
- type code: `type_code`, `typecode`, `type`, `aircrafttype`, `aircrafttypecode`
- manufacturer: `manufacturer`, `maker`
- model: `model`, `aircraftmodel`
- operator: `operator`, `operatorname`, `owner` (optional)

Header matching is case-insensitive and ignores spaces, underscores, hyphens and
dots.

## Behaviour

- Required source columns are validated before any output is written.
- ICAO24, registrations and type codes are normalized to uppercase.
- Invalid rows are skipped and counted.
- Duplicate ICAO24 or registration rows are skipped deterministically; the first
  valid row wins.
- Canonical output is sorted by ICAO24 for reproducibility.
- Output is written through a temporary file and atomically renamed into place.
- If no valid aircraft remain, the existing output file is left untouched.
- Import statistics are printed as `rows`, `imported`, `duplicates` and `invalid`.

## Canonical output schema

```text
icao24,registration,type_code,manufacturer,model,operator
```

The result is directly loadable by the M2.1 aircraft store.

## Acceptance criteria

- [x] CLI import mode exists in the normal Plane Tools binary.
- [x] Common source column aliases are supported.
- [x] Required schema is validated before writing.
- [x] Rows are normalized and validated.
- [x] ICAO24 and registration duplicates are removed deterministically.
- [x] Output order is deterministic.
- [x] Output replacement is atomic.
- [x] Failed/empty imports do not destroy an existing dataset.
- [x] Generated output is accepted by the runtime dataset loader.
- [x] Automated tests cover alias mapping, deduplication, invalid rows, sorting,
      runtime reload and failure safety.
