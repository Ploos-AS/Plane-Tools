# M2.3 — tar1090/readsb aircraft dataset adapter

Status: implemented

## Goal

Allow Plane Tools to ingest the aircraft database format commonly used by
readsb/tar1090 without requiring users to manually rewrite the source file.

## Supported input

`plane-tools import-aircraft` now accepts:

- `--format csv` for the generic header-based M2.2 importer.
- `--format tar1090` for the tar1090/readsb aircraft database format.
- `--format auto` (default): `.gz` input is treated as tar1090; other files use
  the generic CSV importer.

The tar1090/readsb adapter accepts plain files and gzip-compressed files. Its
expected semicolon-delimited field order is:

```text
ICAO;Registration;Type;Flags;Description;Year;Owner/Operator;...
```

The adapter maps fields into Plane Tools canonical data as follows:

- ICAO -> `icao24`
- Registration -> `registration`
- Type -> `type_code`
- Description -> `model`
- Owner/Operator -> `operator`
- `manufacturer` remains empty because this upstream format exposes a combined
  description rather than a separate manufacturer field.

## Usage

With the commonly distributed gzip file:

```sh
plane-tools import-aircraft \
  --input aircraft.csv.gz \
  --format tar1090 \
  --output /data/aircraft.csv
```

Because `.gz` auto-detects as tar1090, this is equivalent:

```sh
plane-tools import-aircraft \
  --input aircraft.csv.gz \
  --output /data/aircraft.csv
```

For an uncompressed tar1090 file, specify the format explicitly:

```sh
plane-tools import-aircraft \
  --input aircraft.csv \
  --format tar1090 \
  --output /data/aircraft.csv
```

## Data source and licensing

Plane Tools contains only an adapter and does not bundle or automatically fetch
third-party aircraft databases. The Mictronics Aircraft Database project states
that its database exports are available under the Open Data Commons Attribution
License. tar1090 documentation commonly points readsb users to the generated
`aircraft.csv.gz` database. Users remain responsible for checking the terms and
provenance of the particular dataset they import.

The tar1090 project also warns that its database format may change. The adapter
is therefore isolated behind the `tar1090` format name and covered by fixtures,
so future upstream format changes can be handled without changing Plane Tools'
canonical `/data/aircraft.csv` contract.
