# M3.2 — Spotting location tools

Status: implemented

## Goal

Add private, local spotting-location storage and airport-relative analysis without external services.

## Storage

Plane Tools uses:

- `/data/spotting-locations.json`
- override with `PLANE_TOOLS_SPOTTING_LOCATIONS`

The file is created on first write. Updates use a temporary file plus atomic rename.

## API

### List saved locations

```sh
curl http://localhost:8080/api/v1/spotting-locations
```

### Save a location

```sh
curl -X POST http://localhost:8080/api/v1/spotting-locations \
  -H 'Content-Type: application/json' \
  -d '{"name":"Kjevik spot","latitude_deg":58.205,"longitude_deg":8.09}'
```

Names are unique case-insensitively and coordinates are validated.

### Analyze a location

```sh
curl 'http://localhost:8080/api/v1/spotting-locations/analyze?lat=58.205&lon=8.09&name=Kjevik%20spot'
```

The response includes:

- the supplied location
- nearest airport from the active local airport dataset
- great-circle distance in nautical miles
- initial true bearing toward that airport

## Privacy

Saved locations remain under `/data`; the analysis uses only local airport data and does not send spotting coordinates to a provider.

## Acceptance criteria

- [x] Missing storage file is non-fatal.
- [x] Locations can be saved and listed.
- [x] Invalid coordinates are rejected.
- [x] Duplicate names are rejected case-insensitively.
- [x] Writes are atomic.
- [x] Nearest airport is determined locally.
- [x] Distance and bearing reuse the existing aviation math.
- [x] Automated tests cover persistence behavior and analysis.
