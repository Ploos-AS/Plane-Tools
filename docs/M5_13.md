# M5.13 — ADS-B diagnostics UI

M5.13 exposes the existing local ADS-B observability data in the embedded web UI without adding telemetry dependencies or creating extra receiver traffic.

## UI

The Live ADS-B section now contains a compact diagnostics card showing:

- receiver health
- cache hit rate
- coalesced request count
- upstream fetch count
- upstream error count and error rate
- last upstream fetch latency
- cache TTL
- last successful fetch time
- feed age / last-success age when available

The card refreshes every 5 seconds and also has a manual Refresh button.

## Local-only refresh path

`adsb-diagnostics.js` calls only:

`GET /api/v1/adsb/diagnostics`

It does not call `aircraft.json`, the receiver URL, `/api/v1/adsb/status`, or `/api/v1/adsb/snapshot`, so diagnostics polling cannot add ADS-B receiver load.

## Diagnostics health

The diagnostics endpoint now includes:

- `configured`
- `health`
- `health_reason`
- `feed_age_seconds` when available
- `last_success_age_seconds` when available

Health is calculated from the already cached feed and M5.10 observability state. Reading diagnostics does not perform an upstream fetch.

## Privacy

The diagnostics response and UI continue to exclude receiver URL, hostname, credentials, coordinates, and aircraft payload data.

## Tests

M5.13 adds tests that verify:

- required diagnostics UI hooks are embedded
- the UI calls only the local diagnostics endpoint
- receiver URL / `aircraft.json` references are absent from diagnostics JS
- cached-feed health is reported as healthy when appropriate
- reading diagnostics does not increment the upstream-fetch counter
