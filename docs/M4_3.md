# M4.3 — Logbook portability

M4.3 makes the local spotting log portable and backup-friendly without adding any external service dependency.

## Export

`GET /api/v1/spotting-log/export`

JSON is the default format. CSV is available with `?format=csv`.

The export endpoint accepts the same filters as the logbook and summary APIs:

- `icao24`
- `registration`
- `airport_ident`
- `spotting_location_id`
- `from`
- `to`

Exports are deterministic and sorted oldest observation first, then by ID.

Examples:

```text
GET /api/v1/spotting-log/export
GET /api/v1/spotting-log/export?format=csv
GET /api/v1/spotting-log/export?airport_ident=ENGM&from=2026-09-01
```

## Import / restore

`POST /api/v1/spotting-log/import`

Supported formats:

- JSON array of spotting log entries
- CSV using the Plane Tools export columns

Format can be selected with `?format=json` or `?format=csv`. If omitted, `text/csv` selects CSV; otherwise JSON is assumed.

Import modes:

- `mode=merge` — default; imported IDs replace matching IDs and new IDs are appended
- `mode=replace` — replaces the complete local log with the imported dataset

Every entry is normalized and validated before the persistent file is changed. Invalid imports therefore leave the current log untouched.

Imported entries require stable IDs so that a JSON/CSV export can be restored without creating duplicate observations.

## Persistence and privacy

Import uses the existing atomic spotting-log persistence path. Data stays in the configured local `PLANE_TOOLS_SPOTTING_LOG` file; no cloud API or external account is involved.

This provides a simple backup/restore path for `/data/spotting-log.json` while also supporting interoperable CSV exports for spreadsheets and other plane-spotting tools.
