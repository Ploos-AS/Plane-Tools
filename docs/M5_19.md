# M5.19 — ADS-B outage statistics

M5.19 adds bounded, local outage aggregates derived from the existing ADS-B health-transition history.

## Scope

The diagnostics response now includes `outage_statistics` with:

- `known`
- `completed`
- `by_class`
  - `blip`
  - `timeout`
  - `upstream_status`
  - `receiver_issue`
  - `receiver_outage`
- `longest_seconds`
- `mean_seconds`
- `time_since_last_outage_seconds`

Only completed outages are included in the aggregate statistics. An outage that is currently active remains available through `current_outage`, but it does not change completed counts, longest duration, or mean duration until a recovery transition closes it.

## Bounded semantics

The statistics are calculated only from health-transition events still present in the in-memory history buffer. The history is bounded to 64 events and is cleared on process restart. These values are therefore diagnostic history-window statistics, not persistent SLA or lifetime metrics.

## UI

The ADS-B diagnostics panel shows:

- completed outage count
- outage counts by class
- longest completed outage
- mean completed outage duration
- time since the most recently completed outage

The existing active-outage and last-outage classification remain visible alongside the aggregates.

## Privacy and receiver isolation

M5.19 does not:

- poll the ADS-B receiver
- persist telemetry
- expose the receiver URL
- store credentials
- expose receiver coordinates
- include aircraft payloads
- retain raw receiver error strings

All calculations use the local bounded event history already introduced by M5.14.

## Qualification

Tests cover:

- multiple completed outages with deterministic class counts
- longest and mean outage duration
- time since the last completed outage
- exclusion of an active outage from completed aggregates
- unknown statistics when no outage has completed
- frontend hooks for outage statistics without direct receiver access
