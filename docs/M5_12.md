# M5.12 — stale-data resilience

M5.12 keeps the local ADS-B radar useful through short receiver interruptions without pretending cached positions are live.

## Behaviour

- A successful ADS-B fetch continues to populate the shared in-memory cache.
- Normal live cache TTL remains 1 second.
- If a later upstream fetch fails, `/api/v1/adsb/snapshot` may reuse the last successful aircraft snapshot for up to 5 minutes.
- Stale fallback is limited to the exact same receiver configuration key: URL, timeout and configured receiver position.
- Receiver reconfiguration therefore cannot inherit stale aircraft or geometry from a previous receiver.
- Stale fallback remains subject to the same aircraft filters and sorting as live snapshots.
- Other legacy ADS-B read endpoints keep their existing error semantics; stale fallback is intentionally scoped to the browser-oriented snapshot API.

## API markers

When stale fallback is used, `status` includes:

- `stale_data: true`
- `stale_data_age_seconds`
- the normal `health`, `health_reason`, `error_code` and `error` values from the failed live fetch
- `aircraft` and `messages` describing the cached snapshot

`reachable` remains false. Cached data is therefore never presented as a successful live receiver fetch.

## UI

The live aircraft list and radar remain populated when recent stale data is available. The receiver status explicitly says that cached data is being shown and includes its age.

If there is no suitable cached snapshot, or it is older than 5 minutes, the previous offline behaviour remains: the aircraft list is cleared and the fetch error is shown.

## Privacy and storage

Stale ADS-B data remains process-memory only. M5.12 adds no persistence under `/data`, no external service, no map provider and no telemetry export.

## Acceptance

- [x] Short receiver failure can return the last good snapshot.
- [x] Stale data is explicitly marked and aged.
- [x] `reachable` stays false during fallback.
- [x] Filter/sort logic applies to stale data.
- [x] Stale fallback expires after 5 minutes.
- [x] Cache never crosses receiver configuration boundaries.
- [x] UI keeps radar/list populated while clearly labelling cached data.
