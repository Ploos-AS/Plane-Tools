# M5.20 — ADS-B privacy and security hardening

M5.20 hardens the public ADS-B API against accidental disclosure of receiver secrets and precise receiver location.

## Public error sanitization

Public ADS-B handlers no longer return raw upstream error text. They expose a stable `error_code` plus a bounded, generic message derived from that code.

This prevents errors from `http.Client.Do`, request creation, response reading, or JSON decoding from accidentally echoing sensitive receiver configuration such as URL userinfo, host details, or credentials.

The `unreachable` fetch path itself also uses a generic internal error message rather than wrapping the raw transport error.

The helper typo `newADSBFetcError` was corrected to `newADSBFetchError`.

## Receiver-coordinate privacy

The public ADS-B status model no longer contains `receiver_lat` or `receiver_lon`.

`GET /api/v1/adsb/status` and the status object inside `GET /api/v1/adsb/snapshot` retain only `position_configured`, which is sufficient for clients to know whether distance/bearing calculations are available without exposing the receiver's precise location.

Receiver coordinates remain server-side and continue to be used for aircraft distance and bearing calculations.

## Regression coverage

M5.20 tests verify that:

- an unreachable receiver configured with URL userinfo such as `secret:token@host` does not leak credentials or host details through status, snapshot, or aircraft responses;
- public errors preserve the stable `unreachable` code while replacing raw detail with a generic message;
- status and snapshot keep `position_configured=true` when receiver coordinates are configured;
- status and snapshot do not expose `receiver_lat`, `receiver_lon`, or the configured coordinate values;
- the public error-message mapping does not expose raw upstream error contents.

## Scope

M5.20 changes public API disclosure only. It does not alter aircraft positions returned by the ADS-B aircraft APIs, receiver-side distance/bearing calculations, local health semantics, event history, availability, outage classification, or outage statistics.
