# M5.26 — ADS-B filter debounce

M5.26 reduces unnecessary live ADS-B snapshot requests while the operator edits filters.

## Behaviour

- Text and numeric filter `input` events are debounced for 250 ms.
- A new input resets the pending debounce timer.
- Filter `change` events refresh immediately.
- Manual refresh refreshes immediately.
- Immediate refresh cancels a pending debounce timer first.
- The existing 5-second auto-refresh remains immediate and unchanged.
- M5.25 request cancellation and latest-request-wins protection remain active for all actual refreshes.

This keeps typing responsive without creating and aborting a snapshot request for every keystroke.

## Scope

No backend API, filtering semantics, radar behaviour, cache semantics, health classification, or polling interval changed in M5.26.
