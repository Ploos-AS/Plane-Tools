# M5.23 — Remove legacy ADS-B code from app.js

## Goal

Make `web/adsb-m52.js` the single owner of the live ADS-B frontend refresh/render lifecycle.

## Changes

- Removed the pre-M5.2 ADS-B implementation from `web/app.js`.
- Removed legacy `/api/v1/adsb/status` + `/api/v1/adsb/aircraft` frontend usage from `app.js`.
- Removed duplicate ADS-B refresh/render scheduling and event bindings from `app.js`.
- Moved live ADS-B DOM references, timer ownership, `formatLiveValue`, `renderADSBAircraft`, `refreshADSB`, and `scheduleADSBRefresh` into `web/adsb-m52.js`.
- `adsb-m52.js` remains snapshot-based and continues to expose the explicit M5.22 live hooks used by the radar module.
- `web/app.js` still owns shared generic helpers and the spotting-log form objects consumed by live ADS-B sighting prefill.

## Ownership after M5.23

`web/app.js`:
- generic API/HTML helpers
- airport/location UI
- spotting-log UI

`web/adsb-m52.js`:
- live ADS-B DOM references
- filters
- snapshot refresh
- live list rendering
- auto-refresh timer
- manual refresh binding
- live ADS-B hooks

`web/adsb-radar.js`:
- radar/trails/selection/follow/freeze behavior through explicit hooks

## Qualification

`web_m523_test.go` prevents legacy live ADS-B ownership from returning to `app.js` and verifies the required ownership symbols exist in `adsb-m52.js`.
