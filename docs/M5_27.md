# M5.27 — ADS-B refresh state UX

M5.27 adds a dedicated live-refresh state surface without weakening the existing receiver health/status presentation.

## Behaviour

- The receiver health line remains the authoritative health/stale/offline surface.
- A separate `#adsb-refresh-state` line reports refresh freshness.
- A refresh that takes longer than 150 ms shows `Refreshing…`.
- Fast normal polls complete before that delay, avoiding visible flicker during the 5-second auto-refresh cycle.
- Successful snapshot responses record the local completion time and show `Updated just now.`, then `Updated Ns ago.` / `Updated Nm ago.` as time passes.
- Failed refreshes keep the previous successful update age while the existing receiver status reports the failure.
- Aborted/stale requests cannot overwrite refresh state because the state helpers use the same M5.25 request sequence guard.

## Scope

This is frontend-only UX state. It adds no persistence, telemetry, receiver polling, or new external requests. The displayed update age is local browser state and resets on page reload.
